## Deck structure (12–15 slides max)

1. Problem (the village you drive past) → 2. Three barriers → 3. Solution (3 differentiators) → 4. Comparison table (Airbnb/Viator vs us) → 5. **Live demo** → 6. How trust works (Panchayat badge + mediation) → 7. Honest scope → 8. Roadmap → 9. Team

## Your key lines (say them out loud in practice)

- The one-liner: *"Airbnb shows you experiences in a city. We show you the villages you were already driving past — and the host lists by speaking, not typing."*
- *"She didn't fill a form. She spoke."*
- *"Airbnb would show you nothing here. These villages aren't destinations — they're on the way."*
- *"Voice in, voice out."*
- *"Direct UPI to the host — and the Panchayat that vets the host also mediates disputes."* (answer the refund question before it's asked)

## The demo run (6 minutes)

1. Problem (0:00–0:30) → 2. Voice listing — the money moment (0:30–1:30) → 3. Route discovery (1:30–2:30) → 4. Detail page + Listen (2:30–3:15) → 5. Booking + UPI (3:15–4:00) → 6. Host dashboard updates (4:00–4:20) → 7. Itinerary (4:20–4:50) → 8. Offline pack (4:50–5:20) → 9. Close (5:20–6:00)

## Demo discipline

- Rehearse 3+ full dry runs on venue Wi-Fi
- **Drill every fallback** until switching layers is invisible
- If a step dies: *"that's the live layer; here's the same moment from our pre-recorded run"* — never "let me fix it"
- Time every segment against the script's timings

## Judge question prep (write answers with the team)

- "What about refunds/disputes?" → Panchayat mediation
- "Why would travellers come to a platform with 15 experiences?" → the route reframe: a village doesn't need to be a destination, only *on the way*
- "Why not a WhatsApp group?" → structure, trust badges, itinerary, booking
- "How do you onboard hosts at scale?" → SHG/Panchayat partnership (honest scope)
- "What's real vs demo?" → be precise and proud: voice pipeline real, UPI simulated

## Dependencies

- **Needs:** working must-ship features from the backend, AI, frontend and maps teammates; real content from the data teammate; sample clips.
- **Gives:** the story, the rehearsal discipline, the backup video — the team's insurance.

## Build order

1. Day 1 — deck skeleton + script skeleton (90% writable before code)
2. Sample voice clips recorded
3. Weekly: one full dry run after every phase
4. Before event: backup recording, final rehearsal, fallback drill
